### Session: 2026-01-22 (Prompt Optimization - Different Formats for Ollama & WebLLM)

**Branch**: master

**Status**: ✅ COMPLETE - Optimized prompts for both backends, preventing echo and ensuring quality

**Progress Summary**:

User reported quality differences between Ollama and WebLLM responses. Initial attempt to unify prompts (commit 3ece090) revealed that few-shot examples work great for WebLLM's chat API but cause echo issues with Ollama's generate endpoint. Solution: Use different prompt formats optimized for each API type.

**✅ Completed**:

1. **Prompt Analysis** - Identified key differences
   - WebLLM: Simplified prompts with few-shot examples (2 per stakeholder)
   - WebLLM: Temperature 0.5, plain text output, echo detection
   - WebLLM: ~100 word prompt asking for 2-3 sentences
   - Ollama: Complex prompt with 7 rules, trying to preserve JSON structure
   - Ollama: Temperature 0.7, no few-shot examples, no echo detection
   - Ollama: ~200 word prompt asking for full response enhancement

2. **Unified Ollama Prompts** - Now uses same prompts as WebLLM
   - Changed from `buildSystemPrompt()` to `buildEnhancementSystemPrompt()`
   - Added `buildEnhancementUserPrompt()` for context
   - Now includes few-shot examples for all 9 stakeholders
   - Lowered temperature from 0.7 to 0.5 (matches WebLLM)
   - Increased num_predict from 400 to 600 (matches WebLLM max_tokens)
   - File: `src/utils/stakeholder-ai.ts` (~30 lines changed)

3. **Added Echo Detection** - Prevents prompt repetition
   - Ollama responses now checked with `isEchoResponse()`
   - Falls back to rule-based if echo detected
   - Same protection as WebLLM

4. **Simplified Parsing** - Matches WebLLM approach
   - Removed complex JSON parsing logic
   - Uses plain text to enhance `initialReaction` only
   - Keeps all other fields from rule-based response
   - More reliable and consistent outputs

5. **Deprecated Old Prompt** - Marked for reference
   - Added `@deprecated` to `buildSystemPrompt()`
   - Function kept for DEBUG scripts but not used in main code

**Key Benefits**:

- ✅ **Consistent quality**: Both backends now produce similar-quality responses
- ✅ **Better stakeholder voices**: Few-shot examples teach correct tone/style
- ✅ **More reliable**: Lower temperature = more consistent outputs
- ✅ **Echo prevention**: Both backends protected from prompt repetition
- ✅ **Simpler task**: Focused on enhancing initialReaction only
- ✅ **Same user experience**: Users get consistent results regardless of backend

**Technical Changes**:

```typescript
// OLD OLLAMA (complex, no examples)
const systemPrompt = buildSystemPrompt(stakeholder, scenario, derivedMetrics);
const baseResponseText = JSON.stringify(ruleBasedResponse, null, 2);
prompt: `${systemPrompt}\n\n${baseResponseText}\n\nENHANCED VERSION...`
temperature: 0.7

// NEW OLLAMA (simplified, with few-shot examples)
const systemPrompt = buildEnhancementSystemPrompt(stakeholder, scenario, derivedMetrics);
const userPrompt = buildEnhancementUserPrompt(ruleBasedResponse, stakeholder);
prompt: `${systemPrompt}\n\n${userPrompt}`
temperature: 0.5
```

**Files Modified**:
- `src/utils/stakeholder-ai.ts` (~30 lines changed - unified prompts, echo detection, simplified parsing)

**❌ Issue Discovered with Initial Unification (commit 3ece090)**:

Testing revealed that using the exact same prompts for both backends caused Ollama to echo the input:
- **WebLLM (chat API)**: Few-shot examples worked perfectly ✅
- **Ollama (generate endpoint)**: Few-shot examples caused echo - model repeated input instead of generating ❌

Example echo response from Ollama:
```
Input: "Positive aspects: High renewable penetration... Concerns: Grid stability..."
Output: "Positive aspects: High renewable penetration... Concerns: Grid stability..."  ← ECHO!
```

**✅ Solution Implemented (commit f283f06)**:

Created separate prompt functions optimized for each API type:

1. **WebLLM**: Keep `buildEnhancementSystemPrompt()` with few-shot examples
   - Chat API (system/user messages) works well with examples
   - Temperature 0.5, max_tokens 600
   - Echo detection enabled

2. **Ollama**: New `buildOllamaSystemPrompt()` with direct instructions
   - Generate endpoint needs simpler, more direct format
   - No few-shot examples (they cause echo)
   - Clear task instructions: "Write 2-3 sentences expressing your perspective"
   - Explicit voice guidance: "Use first-person voice (we, our)"
   - Temperature 0.5, num_predict 600
   - Echo detection enabled

**Testing Verification**:

Tested Ollama prompts with direct curl calls:

```bash

Response: "Positive aspects: High renewable..." ❌

# NEW (simple direct prompt): SUCCESS
Response: "As policy makers and regulators in ScenarioLand, we are committed
to ensuring that the transition towards 82.0% renewable energy by 2030 is
achieved while maintaining energy security..." ✅
```

**Key Findings**:

- ✅ Ollama responses are now first-person, professional, stakeholder-appropriate
- ✅ No echo artifacts
- ✅ WebLLM quality unchanged (still excellent with few-shot examples)
- ✅ Both backends use same temperature (0.5) and token limits
- ✅ Both have echo detection as failsafe
- ✅ Inference time: ~50s on slower hardware (acceptable)
